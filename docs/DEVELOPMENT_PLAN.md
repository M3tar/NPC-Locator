# 联机 NPC 查询器 Mod 开发计划

> 文档状态：需求确认版 v0.2  
> 编写日期：2026-07-31  
> 目标游戏：《星露谷物语》1.6.15（兼顾后续 1.6.x）  
> 目标 SMAPI：4.5.2 及兼容版本  
> 首发平台：Windows 11 / Steam 版联机  

## 1. 项目摘要

本项目拟开发一个独立的 SMAPI Mod，名称确定为“NPC 定位器”（英文 `NPC Locator`）。它最初解决《星露谷物语》联机时非主机玩家无法通过 Lookup Anything 获取远端 NPC 实时位置及当天完整日程的问题，现已扩展为适用于单人玩家、联机主机和农场助手的独立查询与追踪工具。

Mod 不修改 Lookup Anything，也不要求 Lookup Anything 作为依赖。主机与需要查询的联机玩家安装同一个 Mod 后，非主机玩家可以发起 NPC 查询；主机端读取完整世界状态，再将允许共享的信息返回给查询者。主机端默认静默运行，不弹窗、不暂停游戏、不改变 NPC 行为，也不修改存档。

首版面向原版 NPC。代码结构预留对 Stardew Valley Expanded、Ridgeside Village、East Scarp 及其他标准自定义 NPC 的兼容能力，但不会在没有相应测试环境时承诺完整支持。

## 3. 问题定义

### 3.1 原始问题

Lookup Anything 在非主机端只能访问游戏已同步给该玩家的活动地图。NPC 位于未同步地图时，当前位置显示为未知；完整日程则在非主机端直接隐藏。这会妨碍送货、交谈、交付任务与日常送礼。

### 3.2 根本原因

这是游戏联机同步模型造成的数据可见性差异，而不是 Lookup Anything 安装失败：

- 主机拥有完整世界与 NPC 状态。
- 非主机通常只收到当前地图、农场、农舍及部分活动地点的数据。
- NPC 的完整当日日程主要在主机端可靠可用。

因此，单独安装在非主机端的 Mod 无法凭空恢复完整数据；主机必须同时安装本 Mod并响应查询。

### 3.3 解决策略

采用“主机权威、客户端请求”的独立联机协议：

1. 客户端选择 NPC 并发出查询。
2. 主机验证请求者与功能权限。
3. 主机读取该 NPC 的实时状态及标准日程。
4. 主机返回结构化结果。
5. 客户端使用自己的语言显示信息，并按需持续追踪。

SMAPI 官方支持按玩家与 Mod ID 定向发送消息，也明确说明非主机只同步活动地点，因此该方案符合 SMAPI 的标准联机模型：

- [SMAPI 联机 API](https://wiki.stardewvalley.net/Modding%3AModder_Guide/APIs/Multiplayer)
- [SMAPI Mod 入门与构建方式](https://wiki.stardewvalley.net/Modding%3AModder_Guide/Get_Started)

## 4. 产品目标与非目标

### 4.1 首要目标

1. 非主机玩家能够查询原版 NPC 的实时地图位置。
2. 非主机玩家能够查看主机端实际生成的当天标准日程。
3. 玩家能够固定追踪一名 NPC，并随游戏时间自动刷新。
4. 玩家能够从自己的送货任务中识别目标 NPC，并选择开始追踪。
5. 主机端无感运行，不干扰正常游戏流程。
6. Mod 不修改存档，随时可移除。
7. 查询界面支持简体中文与英文。
8. 默认 F3 打开查询器，并支持完整自定义按键。

### 4.2 明确非目标

首版不实现以下功能：

- 自动走路、自动寻路或自动交付任务。
- 将玩家传送到 NPC 身边。
- 修改 NPC 日程、位置、对话或任务进度。
- 读取未安装本 Mod 的主机数据。
- 强行修改或嵌入 Lookup Anything 内部界面。
- 承诺对所有自定义 NPC、特殊订单和剧情 Mod 完整兼容。
- 将玩家任务内容上传到主机；任务识别只在查询者本地进行。

## 5. 用户体验设计

### 5.1 打开查询器

- 默认按键：`F3`。
- 使用 SMAPI `KeybindList` 保存绑定，支持键盘组合键、鼠标键与手柄键。
- 如果已安装 Generic Mod Config Menu，可在游戏内修改按键。
- 未安装 GMCM 时，可编辑本 Mod 自动生成的 `config.json`。
- 可将按键设置为空，关闭快捷键入口。
- 配置保存后立即应用，无需重启游戏。
- 单人玩家、联机主机和联机农场助手均可主动打开查询器；主机查询直接读取本机权威数据。

#### 按键冲突边界

SMAPI 没有提供可靠的全局“某按键已被其他 Mod 占用”注册表，因此本 Mod不能保证提前检测 F3 是否被其他 Mod 使用。如果两个 Mod 同时响应 F3，玩家需要在 GMCM 中修改其中一个按键。本项目将提供清晰说明，但不承诺自动解决所有冲突。

### 5.2 主查询窗口

推荐采用标准游戏风格的双栏界面：

- 左栏：NPC 搜索与列表。
- 右栏：所选 NPC 的实时位置、状态与当天日程。
- 顶部：搜索框，可按显示名称搜索。
- 底部：查询、追踪/取消追踪、刷新、关闭按钮。

NPC 列表默认只展示可识别的村民类 NPC，排除怪物、宠物、马、临时节日角色和不可交互角色。后续可在配置中增加“显示所有可查询角色”。

### 5.3 查询结果

正常结果示例：

```text
乔迪

当前位置：柳巷 1 号
坐标：12, 8
状态：正在按照日程行动

今日安排
09:00  柳巷 1 号
11:30  鹈鹕镇
15:20  皮埃尔的杂货店
19:00  柳巷 1 号

[开始追踪] [立即刷新]
```

客户端显示时优先使用游戏自带的本地化 NPC 名称和地点名称。主机同时返回内部名称与显示名称作为兼容回退。

### 5.4 追踪栏

选择“开始追踪”后，在屏幕角落显示紧凑信息：

```text
📍 乔迪
当前位置：柳巷 1 号
下一站：鹈鹕镇
```

行为规则：

- 每个游戏时间刻度（通常游戏时钟变化时）刷新一次。
- NPC 换地图时立即更新，前提是能够从主机获得新状态。
- 玩家与 NPC 在同一地图时，可显示大致方向和格子距离。
- 默认只允许同时追踪一名 NPC，避免界面与网络噪声。
- 切换存档、返回标题、断线或 NPC 不存在时自动清理追踪状态。
- 不把追踪对象写入游戏存档；可选地写入 Mod 自己的按存档配置，以便次日继续追踪。

### 5.5 送货任务识别

本功能只读取查询者自己的任务日志：

1. 检测活动中的标准物品交付任务。
2. 提取目标 NPC、物品、数量与剩余时间。
3. 当发现尚未处理的新任务时，显示一次非阻塞提示。
4. 玩家选择“追踪”后，将该 NPC 设置为当前追踪目标。
5. 完成、取消或过期后自动停止任务关联追踪。

推荐默认模式为“识别后询问”，而不是自动覆盖当前追踪对象。

第一版只正式支持游戏的标准物品交付任务。特殊订单、自定义任务类型或一个任务涉及多个 NPC 时，只保持原有任务显示，不自动推断目标。

## 6. 主机端体验与权限

主机不会因为农场助手发起远程查询而自动显示窗口或通知。主机玩家主动按下查询快捷键时，可以使用与农场助手相同的查询和追踪界面；该查询直接读取本机权威数据，不经过联机消息。主机正常钓鱼、战斗、对话或暂停时，本 Mod 只在后台处理很小的结构化消息。

建议主机配置：

| 配置项 | 默认值 | 说明 |
|---|---:|---|
| `AllowRemoteQueries` | true | 是否允许非主机查询 |
| `ShareCurrentLocation` | true | 是否共享实时位置 |
| `ShareDailySchedule` | true | 是否共享完整标准日程 |
| `ShowHostNotifications` | false | 主机是否看到查询提示 |
| `MaxRequestsPerSecond` | 4 | 单个玩家的请求频率上限 |

权限规则：

- 只响应当前联机存档中已连接的玩家。
- 只响应相同 Mod ID 与兼容协议版本发出的消息。
- 不接受客户端提供任意类型名、文件路径或可执行指令。
- 客户端只能提交 NPC 内部名称及查询选项。
- 主机可以关闭全部远程查询，但本地查询仍可工作。

### 7.3 主要模块职责

#### `NpcLocatorService`

- 在主机端按内部名称寻找 NPC。
- 读取当前地图、格子坐标及 NPC 状态。
- 区分标准村民、临时实例、节日角色和不存在角色。
- 优先返回实时位置，不根据日程猜测当前位置。

#### `ScheduleFormatter`

- 读取主机端 NPC 当天已生成的标准日程。
- 按时间排序并生成结构化条目。
- 保留地点内部名称、显示名称、目标格子与时间。
- 判断 NPC 是否忽略或停止遵循日程。
- 不把“计划到达时间”描述成精确实时位置。

#### `QuestTrackingService`

- 在查询者本地扫描活动任务。
- 识别标准物品交付任务及目标 NPC。
- 对同一任务只提示一次。
- 监控任务完成、移除与过期。
- 不将玩家任务详情发送给主机。

#### `NpcSearchMenu`

- 提供搜索、NPC 选择、结果显示与追踪控制。
- 使用游戏字体、按钮与九宫格背景，保持原版视觉风格。
- 适配常用分辨率、UI 缩放与键鼠操作。
- 手柄完整导航列为首版后半阶段验收项。

#### `NpcTrackerOverlay`

- 绘制当前追踪 NPC 的紧凑信息。
- 可配置屏幕角落、透明度与是否显示下一站。
- 避让常见 HUD 区域，但不承诺自动避开所有第三方 HUD Mod。

## 8. 联机通信协议

### 8.1 消息类型

建议使用以下消息：

```text
ProtocolHello
NpcQueryRequest
NpcQueryResponse
NpcTrackingStop
```

### 8.2 查询请求

```json
{
  "ProtocolVersion": 1,
  "RequestId": "guid",
  "NpcName": "Jodi",
  "IncludeSchedule": true
}
```

### 8.3 查询响应

```json
{
  "ProtocolVersion": 1,
  "RequestId": "guid",
  "Status": "Success",
  "NpcName": "Jodi",
  "NpcDisplayName": "乔迪",
  "LocationName": "JoshHouse",
  "LocationDisplayName": "柳巷 1 号",
  "TileX": 12,
  "TileY": 8,
  "IsFollowingSchedule": true,
  "Schedule": []
}
```

`Status` 至少支持：

- `Success`
- `NpcNotFound`
- `LocationUnavailable`
- `ScheduleUnavailable`
- `PermissionDenied`
- `UnsupportedProtocol`
- `HostNotReady`

### 8.4 通信行为

- 客户端打开 NPC 详情时发送一次查询。
- 手动刷新时发送一次查询。
- 追踪状态下仅在游戏时间变化或明确地图变化时查询，避免逐帧通信。
- 请求设置唯一 ID，过期响应不会覆盖更新结果。
- 超时后显示“主机未响应”，不冻结 UI。
- 若主机未安装本 Mod，客户端在连接信息中检测并直接提示，不持续发送无效请求。
- 若主机与客户端协议版本不兼容，显示明确版本错误。

## 9. 特殊情况与真实性边界

### 9.1 节日与剧情事件

节日、婚礼、剧情事件或脚本场景中，NPC 可能没有普通日程，或存在临时 NPC 实例。本 Mod 应：

- 始终优先显示主机端实时位置。
- 将日程标记为“今日由事件控制，标准日程不可用”。
- 不用 Wiki 固定表或客户端推算结果冒充实时数据。

### 9.2 NPC 未找到

日志中曾出现事件执行时 `NPC 'Pam' not found`。因此主机端查询必须允许 NPC 暂时不存在：

- 返回 `NpcNotFound`，不抛出未处理异常。
- 追踪状态保留并在下一游戏时间刻度重试。
- 连续多次失败后显示“NPC 暂不可定位”。

### 9.3 非标准日程

以下情况可能只有实时位置、没有完整日程：

- NPC 今日忽略日程。
- NPC 由事件、任务或其他 Mod 脚本控制。
- 自定义 NPC 没有使用标准 `NPC.Schedule`。
- 临时角色或节日替身。

界面必须区分“无日程”“日程不可用”和“NPC 不遵循日程”，不能统一显示为程序错误。

### 9.4 地点名称

- 优先调用游戏地点显示名。
- 找不到本地化显示名时使用主机返回的显示名。
- 仍不可解析时显示内部地图名，并加注“自定义地点”。

### 9.5 断线与暂停

- 主机断线：关闭远程结果等待，保留最后一次结果并标记过期。
- 客户端重连：重新握手并重新查询追踪目标。
- 全局暂停或菜单暂停：不重复刷新。
- 返回标题：清空所有会话状态。

## 11. 本地化

### 11.1 首发语言

- `default.json`：英文，作为缺失翻译回退。
- `zh.json`：简体中文。

### 11.2 本地化原则

- 不硬编码 NPC 的中文名与地点翻译。
- 优先使用游戏当前语言的数据。
- Mod 自有提示、按钮、错误和设置全部进入 i18n 文件。
- 网络消息传稳定内部值，不以中文文本作为逻辑判断条件。

## 12. 开发阶段

### 阶段 0：构建与 API 验证

目标：验证本地可构建环境、游戏引用和 1.6.15 API。

任务：

- 创建 .NET 6 SMAPI 项目与 manifest。
- 引入 ModBuildConfig。
- 验证 `dotnet build`。
- 验证 NPC 查找、地点显示名与 `NPC.Schedule` 的实际成员。
- 验证标准物品交付任务在 1.6.15 中可稳定读取的字段。
- 确认 1.6.16 是否存在影响任务类型或编译兼容性的变化。

退出标准：最小 Mod 可加载，控制台无本 Mod 错误。

### 阶段 1：主机查询核心

目标：完成最小可用的请求—响应闭环。

任务：

- 建立协议模型和版本握手。
- 非主机发送 NPC 名称请求。
- 主机返回实时位置和标准日程。
- 客户端先以 HUD 消息或简单菜单显示结果。
- 添加权限、超时、断线与 NPC 不存在处理。

退出标准：两台客户端中，非主机能够查询一个远端 NPC，并看到与主机一致的位置。

### 阶段 2：正式查询 UI

目标：替换临时输出，交付可日常使用的搜索界面。

任务：

- NPC 列表、搜索框与详情面板。
- 日程时间线与状态提示。
- 手动刷新与错误状态。
- F3 / 自定义 KeybindList。
- GMCM 集成。
- 中英文翻译。

退出标准：不需要控制台命令即可完成所有基础查询。

### 阶段 3：追踪栏

目标：持续显示目标位置，减少重复查询操作。

任务：

- 单 NPC 追踪状态。
- 游戏时间变化刷新。
- 同地图方向与距离。
- 切换地图、次日、断线和返回标题清理。
- 位置与透明度配置。

退出标准：连续一个游戏日追踪不产生明显卡顿、刷屏或错误。

### 阶段 4：任务识别

目标：从标准送货任务快速进入 NPC 追踪。

任务：

- 识别标准物品交付任务。
- 去重提示。
- “追踪/忽略”交互。
- 显示物品、数量、持有状态与期限。
- 完成/过期时停止任务关联。

退出标准：至少覆盖一个剧情交付任务和一个公告栏随机交付任务。

## 14. 验收标准

第一版完成需同时满足：

1. 双方使用游戏 1.6.15、SMAPI 4.5.2 时可加载。
2. 非主机可查询不在自己活动地图中的原版 NPC 实时位置。
3. 非主机可查看主机端存在的当天标准日程。
4. 节日、事件和无标准日程状态不会崩溃，也不会显示伪造信息。
5. F3 为默认键，可通过 GMCM 或配置文件修改。
6. 可追踪一名 NPC，位置随游戏时间更新。
7. 可识别标准送货任务并询问是否追踪。
8. 主机端默认无弹窗，不暂停、不修改游戏状态。
9. Mod 不修改存档；删除 Mod 后存档仍可正常使用。
10. 中英文界面均不存在明显缺失文本。
11. 双方 SMAPI 日志中没有由本 Mod 产生的未处理错误。
12. 提供可安装 zip、源代码、README、配置说明与已知限制。

## 15. 风险与缓解措施

| 风险 | 影响 | 缓解方式 |
|---|---|---|
| 游戏 1.6.16+ 内部 API 改变 | 编译或运行失效 | 将版本相关逻辑隔离；先做 API 验证；避免 Harmony |
| NPC 由事件控制 | 无完整日程 | 实时位置优先，明确显示事件状态 |
| 主机未安装 Mod | 客户端无法查询 | 连接时检测并给出明确提示 |
| 第三方 NPC 不使用标准日程 | 只能返回当前位置 | 首版声明边界；后续提供兼容适配层 |
| 快捷键与其他 Mod 冲突 | 两个界面同时打开 | KeybindList + GMCM 自定义；文档提示 |
| 查询过于频繁 | 主机性能或网络噪声 | 游戏时间刻度刷新、缓存与限频 |
| Lookup Anything 更新 | 潜在兼容问题 | 完全独立，不引用其 DLL 或内部类 |
| UI 与其他 HUD 重叠 | 可读性下降 | 可配置位置与透明度；提供关闭追踪栏选项 |

## 17. 已确认的产品决策

以下决策已由用户确认，后续开发原则上按此执行；如技术验证证明某项不可行，必须先更新决策记录并说明原因：

1. **名称**：NPC 定位器 / NPC Locator。
2. **作者**：Mercury。
3. **唯一 ID**：`Mercury.NpcLocator`。
4. **版本**：从 0.1.0 私人内测版开始。
5. **发布准备**：按未来公开发布标准组织代码与文档，首版先私下测试。
6. **快捷键**：默认 F3，使用 KeybindList，可通过 GMCM 或配置文件修改。
7. **语言**：简体中文与英文。
8. **主机权限**：首版只提供远程查询、实时位置与完整日程三个总开关，不做逐玩家授权。
9. **追踪数量**：同时追踪一名 NPC。
10. **追踪持久化**：手动追踪跨游戏日保留，但退出或重新载入存档后清除；任务追踪在任务完成、取消或过期后取消。
11. **任务提示**：使用非阻塞角落提示，识别后询问是否追踪，不强制覆盖当前目标。
12. **同地图指引**：首版显示文字方向与距离；方向箭头作为后续增强。
13. **手柄支持**：首版保证基础兼容与可绑定手柄按键，完整菜单导航后续完善。
14. **版本范围**：最低支持游戏 1.6.15，并尽力兼容后续 1.6.x；避免依赖 1.6.16 才新增的 API。
15. **开发顺序**：联机通信 → 查询界面 → 持续追踪 → 任务识别 → 方向箭头。
16. **日程表述**：界面使用“实时位置”和“今日标准日程”两个概念；事件控制时不伪造预测。
17. **快捷键冲突**：接受 SMAPI 无法可靠提前检测所有第三方按键冲突的限制，以自由改键和文档说明解决。
